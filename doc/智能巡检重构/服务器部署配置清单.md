# 智能巡检平台 · 服务器部署配置清单

## ⭐ 当前实际部署形态：混合模式（Windows 本机 jar + Docker 中间件）—— 2026-09-13 迁移

**为什么**：Docker 容器内 SIP 信令被 NAT 挡死，国标点播/回放不通；WVP jar 直跑 Windows 宿主机、SIP 绑真实网卡 192.168.0.100:5060 后**国标立即全通**。MySQL/Redis/ZLM/nginx 留 Docker（工作正常，无需动）。

**分工**：
| 组件 | 位置 | 说明 |
|---|---|---|
| WVP jar | Windows 本机（`scripts/start-wvp-local.bat`） | SIP 5060、HTTP 18978，前端在 jar 里 |
| MySQL | Docker（新增端口映射 33061→3306） | 数据不变 |
| Redis | Docker（新增端口映射 16379→6379） | |
| ZLM | Docker（8081/10001/10002/10003/30000-30500 映射） | hooks 指向 `host.docker.internal:18978` |
| nginx | Docker 9080（局域网入口） | /api → `host.docker.internal:18978` |
| yolo | Docker 8999 | WVP 经 `http://127.0.0.1:8999` 调用 |

**启动顺序**：开机后 → Docker Desktop 自动起（mysql/redis/media/yolo 自动恢复；nginx 需手动 `docker compose -f docker/docker-compose.yml up -d --no-deps polaris-nginx`）→ 双击 `scripts/start-wvp-local.bat`。
**⚠ 不要用 `docker compose up -d polaris-nginx`**（不带 --no-deps 会把 polaris-wvp 容器依赖拉起来抢 5060 端口）。

**关键坑（都踩过）**：
1. `RUN_ENV=docker` 绝不能给本机 jar 设——那是容器 NAT 的 ShowIP 补丁，本机走真实网卡。
2. `wvp_device.stream_mode` 每设备一存，海康系实测必须 **UDP**（TCP-PASSIVE 收不到流）；stock 注册默认值已改 UDP。
3. 本机 jar 的 jwk 密钥在仓库根 `config/jwk.json`（与容器时代的 `docker/wvp/config/jwk.json` 不同，两者 token 不通用）。
4. 本机模式环境覆盖：`PATROL_CAPTURE_ZLM_API_URL=http://127.0.0.1:8081`、`PATROL_MEDIA_UPLOADDIR=docker/volumes/patrol-media 绝对路径`、`YOLO_URL=http://127.0.0.1:8999`（见 start-wvp-local.bat，全部有注释）。
5. Docker Desktop 端口转发器（com.docker.backend）对已删容器的端口释放有粘滞；杀 backend 进程即可（引擎在 WSL 会自动重启）。杀 backend 会让 Docker Desktop 整个退出，重新运行 Desktop exe 即可。

**生产部署（Linux）**：下文通用清单仍适用于 Linux 服务器部署（jar 直装或 host 网络 Docker），届时删除本节混合模式说明。

## 1. 一张表：所有"地址类"必改项

设：服务器对客户端可达的 IP = `<SERVER_IP>`（内网部署就是内网 IP；有域名用域名）。

| # | 配置项 | 位置 | 现值（开发机） | 服务器应改为 | 说明 |
|---|---|---|---|---|---|
| 1 | `wvp_media_server.stream_ip` | 数据库 `wvp` 库（或界面：媒体与级联→媒体节点→编辑） | 127.0.0.1→已改 192.168.0.100 | **`<SERVER_IP>`** | **播放地址里的主机名**。错=只有服务器本机能看视频 |
| 2 | `wvp_media_server.sdp_ip` | 同上 | 192.168.0.100 | **`<SERVER_IP>`** | 国标点播时 SDP 里告诉设备"把流推到哪"，必须设备可达 |
| 3 | `wvp_media_server.ip` | 同上 | polaris-media（容器名） | 容器网络内保持 `polaris-media` 不变 | 容器互访地址，**不要**改成外网 IP |
| 4 | `.env Stream_IP` | docker/.env | 127.0.0.1→已改 192.168.0.100 | **`<SERVER_IP>`** | nginx 用它把流地址改写为相对路径；**必须与 #1 一致**（一对） |
| 5 | `.env SIP_ShowIP` | docker/.env | 192.168.0.100 | `<SERVER_IP>` | SIP 配置页展示用 |
| 6 | `.env WebHttp / WebHttps` | docker/.env | 9080 / 9081 | 按需（80/443 亦可） | 用户访问端口 |
| 7 | `sip.ip` | docker/wvp/wvp/application-docker.yml | 0.0.0.0 | 0.0.0.0 保持 | SIP 监听地址 |
| 8 | 设备端国标 SIP 服务器地址 | **每台设备/NVR 的 Web 页** | 指向 192.168.0.100:5060 | **`<SERVER_IP>`:5060** + 平台 SIP 编号/密码 | 改了平台 IP 必须逐台改设备端，否则设备全部离线 |
| 9 | 摄像机 RTSP 源地址 | 界面：设备管理→编辑 | rtsp://…@192.168.0.125:554/… | 新网络里摄像机的实际地址 | 用"测试连通"验证后保存 |
| 10 | YOLO 服务地址 | 界面：智能算法→算法页顶部 | http://yolo-service:8999 | **保持不变**（容器名互通，勿写 127.0.0.1） | 写错=识别静默退化 |

> **配对提醒**：#1 与 #4 是一对（一个生成绝对流地址、一个负责改写成相对地址），必须同值同改。
> **偷懒替代**：可在 application-docker.yml 的 user-settings 打开 `use-source-ip-as-stream-ip: true`，平台按"浏览器访问用的地址"自动生成流地址（多网卡/内外网混合部署最省事；有反向代理时需确认传递 Host 头）。

## 2. 服务器防火墙放行清单（缺一不可）

| 端口 | 协议 | 用途 | 不放行的后果 |
|---|---|---|---|
| 9080（WebHttp） | TCP | 平台页面/API | 用户打不开平台 |
| 8081 | TCP | **实时预览 FLV/fMP4、平台录像 mp4 点播** | 能登录但看不了视频 |
| 5060 | UDP+TCP | 国标 SIP 注册/信令 | 国标设备无法注册 |
| 10003、30000-30500 | UDP(+TCP) | 国标 RTP 收流 | 国标点播"收流超时" |
| 10002 | TCP | RTSP（调试/第三方取流，可选） | — |
| 8999 | TCP | YOLO（一般不对外开放） | — |

Linux 示例（firewalld）：
```bash
firewall-cmd --permanent --add-port=9080/tcp --add-port=8081/tcp \
  --add-port=5060/udp --add-port=5060/tcp \
  --add-port=10003/udp --add-port=30000-30500/udp
firewall-cmd --reload
```

> **Windows 开发机的教训**（已踩过）：Docker Desktop(WSL2 后端)发布的端口默认**只有 127.0.0.1 能进**，需要 ①防火墙放行端口 ②`netsh interface portproxy add v4tov4 listenaddress=0.0.0.0 listenport=9080 connectaddress=127.0.0.1 connectport=9080`（8081 同理）做一层桥，局域网才能访问。**Linux 服务器无此问题，无需 portproxy。** 本开发机已配置：防火墙 7 条规则 + portproxy 2 条（9080/8081）。

## 6. 国标（GB28181）启用条件

- 代码已支持（注册/目录/点播/云台/预置位/级联），**无需开发**。
- 开发机失败的根因是 Docker Desktop 的 NAT：设备注册源地址被改写成容器网关（`172.16.5.1`），平台主动发 INVITE 到不了设备（日志：`点播失败 -1024 消息超时未回复`）。
- **Linux 服务器 + 容器端口正确映射（5060 + RTP 端口段）即恢复正常**；若仍有问题，用 `network_mode: host` 部署 wvp 一劳永逸。
- 届时在设备端把 SIP 服务器指向 `<SERVER_IP>:5060`，重新注册后，"国标设备"页会出现该设备及其通道。

## 7. 已知限制（部署后依然存在，按需排期）

1. **OCR**：`/v1/ocr_detect` 与 `/v1/detect` 目前同为 YOLOv8（无独立 OCR 模型），文字识别靠 VLM 兜底；如铭牌/表计精度不足，可容器化 PaddleOCR 接入（内存预算 ~500MB）。
2. **离线时长/在线率报表**未实现（无离线事件日志表）。
3. **台账按物理设备聚合去重**未实现（同一镜头多路径接入显示多行）。
4. **录像保留策略**未实现（磁盘会持续增长，建议先配 cron 清理 `volumes/video` 下 N 天前的文件，或排期实现按天保留）。
5. **并发上限**：RTP 收流端口段 500 个 ≈ 500 路并发取流；更大规模需扩端口段或多媒体节点。
6. 巡航/守望/OSD/隐私遮挡/上墙/RAID：平台不做，需厂商 NVR 能力（采购决策）。

## 8. 本次开发机为打通"局域网观看"所做的改动（供对照）

1. Windows 防火墙入站放行：9080/tcp、8081/tcp+udp、10002/tcp、5060/udp+tcp、30000-30500/udp（规则名 `WVP-*`）。
2. `wvp_media_server.sdp_ip/stream_ip` 与 `.env Stream_IP` 统一改为 192.168.0.100（已验证：播放接口下发的流地址带 192.168.0.100:8081；mp4 点播经 nginx 路由 200）。
3. **Windows 验证的坑（Linux 服务器不会遇到）**：
   - Docker Desktop(WSL2 后端)发布的端口，**本机用"自己的局域网 IP"访问会超时**（localhost 转发机制只认 127.0.0.1）——这是本机回环假象，**不代表局域网其它设备不通**；本机自测请一律用 `http://127.0.0.1:端口`。
   - `netsh portproxy` 若绑 `0.0.0.0:端口` 会**抢掉 WSL2 的 localhost 转发**导致 127.0.0.1 反而断；要绑就绑**具体网卡 IP + 不同外部端口**（本机已有先例：`192.168.0.100:19080 → 127.0.0.1:9080`、`:18081 → :8081`，作为局域网访问的后备入口）。
   - 最终确认请用**同一有线网段（192.168.0.x）的另一台设备**访问 `http://192.168.0.100:9080`（后备 `:19080`）。注意：WiFi 网段（192.168.31.x）默认路由不到 192.168.0.x，需路由器配静态路由或客户端直连有线网。

## 9. 国标设备"删了又出现"的说明

设备端配置了国标注册（SIP 指向平台），**平台侧删除后，设备下次心跳/重注册会自动再次上线并重建通道**——这是国标的正常行为。要彻底移除：到设备 Web 页（配置→网络→平台接入/GB28181）**关闭注册或改指向**；或在设备端保留注册、接受台账里多一条（当前该通道因 Docker NAT 无法出流，显示为不可用）。
