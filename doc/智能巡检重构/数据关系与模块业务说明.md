# 智能巡检平台 · 数据关系与模块业务全景

> 本文档回答四个问题：**每个模块是干什么的、每张表存什么、表之间怎么关联、人工操作的每一步数据怎么流动**。
> 依据：2026-09-13 全量代码核对（接口/SQL 均在运行系统中验证过）。

---

## 一、系统全景：四个角色

| 角色 | 是什么 | 有没有状态 | 职责边界 |
|---|---|---|---|
| **WVP**（大脑） | Java 平台，`18978` | **有**（MySQL + Redis） | SIP 信令、设备/通道台账、录像计划、云台指令、用户权限、巡检业务全逻辑 |
| **ZLM**（素材引擎） | 流媒体服务器，`8081` | **无**（无数据库） | 收流/转协议(flv/hls/rtsp)、按需拉 RTSP、录 MP4、抓帧。**状态一律问 ZLM 要** |
| **厂商 NVR / PVR**（可选存储节点） | 海康等录像设备 | 有（自管） | 本机录像、录像检索、云台下发中转。平台通过 ISAPI(80)/RTSP(554) 对接 |
| **AI 服务**（平台侧） | yolo_service.py(8999) + VLM 模型 | 无 | YOLO 目检 + 大模型研判。**两条 AI 路线都走平台**，端侧 AI 只作告警来源（待接） |

**核心原则：一台摄像机 = 通道表一行，不管它从哪条路接入。** 用户只关心摄像机；接入方式、拉流任务、SIP 注册都是系统自动派生的"运行载体"。

## 三、每张表：业务含义与关联

### 3.1 资产核心（一台摄像机一行）

| 表 | 存什么 | 关键字段 | 被谁关联 |
|---|---|---|---|
| **wvp_device_channel** | **摄像机/通道台账（核心）** | `data_type`(1国标/2推流/3拉流代理)、`data_device_id`→运行载体id、`stream_id`→流标识、`gb_device_id`(国标编号)、`gb_civil_code`→区划、`record_plan_id`→录像计划 | 几乎所有业务表的外键源头 |
| wvp_device | 国标 SIP 注册设备（PVR/NVR/摄像机本体注册上来的） | `device_id`(20位国标号)、在线=注册心跳 | 通道的 `device_id` 指向它（国标通道的载体） |
| wvp_stream_proxy | ZLM 拉流任务（RTSP直连通道的载体） | `app/stream`(流标识)、`src_url`(RTSP源，含账密)、`pulling`、`enable_mp4` | 通道 `data_device_id` = 它的 id |
| wvp_media_server | ZLM 存储节点（自研） | `stream_ip`(给播放地址用的对外IP)、`record_path` | cloud_record、播放地址 host |

### 3.2 存储与录像

| 表 | 存什么 | 关键字段 | 关联 |
|---|---|---|---|
| patrol_nvr | 厂商录像设备档案（录像设备(NVR)页签） | ip / rtsp_port / api_port / username / password(ISAPI) | 被 patrol_nvr_camera 引用 |
| patrol_nvr_camera | 通道↔NVR 挂载 | `channel_id`、`nvr_id`、`nvr_channel_no`(NVR侧通道号) | 挂载后：取流URL走NVR、云台经NVR ISAPI下发 |
| patrol_channel_storage | 通道录像归属 | `channel_id`、`storage_type`(ZLM/NVR/NONE)、`nvr_id` | 设为NVR时同时写挂载 |
| wvp_record_plan + item | 平台录像计划（7×24或时段） | item: `start/stop/week_day` | 通道 `record_plan_id` 关联 |
| wvp_cloud_record | ZLM 录像索引（ZLM on_record_mp4 hook 上报） | app/stream/文件名/起止时间/file_size | 回放页数据源；按 media_server_id 汇总容量 |

### 3.3 巡检业务

| 表 | 存什么 | 关联 |
|---|---|---|
| patrol_task | 巡视任务（名称/模式/周期） | → task_point |
| patrol_task_point | 任务点位（顺序、绑定通道、绑定识别方案） | channel_id → 通道；scheme_id → 方案 |
| patrol_task_execution | 执行单（一次运行：进度/状态） | task_id；手动识别为 NULL |
| patrol_point_result | 识别结果（result/confidence/yolo_json/vlm/anomaly_reason/review_status） | execution_id/task_id/waypoint_name；media_id → patrol_media |
| patrol_media | 抓帧与录像证据 | point_result_id；path/url 指向磁盘或 ZLM |
| patrol_point_reading | 表计/读数类识别的结构化读数 | point_result_id |
| patrol_alarm | 告警（含级别/状态/恢复） | result_id；DEVICE 源=端侧设备告警(待接) |
| patrol_notification | 站内通知 | user_id(NULL=全体) |
| patrol_maintenance_area | 检修区域（时段内抑制告警） | area_json(区划/点位列表)，status ACTIVE/DISABLED |
| patrol_knowledge_base / doc | 知识库/标准值文档（VLM 复核上下文） | doc.kb_id |
| patrol_dict | 字典（识别类型/告警等级等）+ `type='sys_config'` 存系统配置（yolo_url、告警规则JSON） | — |

### 3.4 AI 配置（方案 = 一次识别的全部参数）

```
patrol_identify_scheme（识别方案，用户在智能算法页配置）
  algo_id    → patrol_algo        YOLO 算法（模型文件/置信度阈值，服务=yolo_service.py）
  model_id   → patrol_vlm_model   大模型（供应商/api_key/模型名）
  prompt_id  → patrol_prompt      提示词（研判规则，占位符填充）
  knowledge_id → patrol_knowledge_base → doc  标准值（VLM 复核时检索注入）
  threshold / types_json                       判定阈值与识别类型
```
另：**patrol_analyzer** 分析器注册表（`type`=yolo/vlm/ocr/audio/video/pointcloud、`engine`/`endpoint`/`params_json`，
多模态可插拔预留）——智能算法页通用 CRUD 已通，但分析链当前实际取数仍走 scheme→algo/vlm_model，**尚未接线**。

### 3.5 装备层（机器狗，对接方式确定后启用）

patrol_robot_device（机器人档案）→ patrol_device_profile（型号能力档案）→ patrol_protocol_template（大疆上云API/云深处/宇树/Spot/通用HTTP/MQTT 模板，endpoints 定义 status/startTask/gotoWaypoint/capturePhoto 等）→ patrol_waypoint/patrol_route（机器狗点位/路线）。**定时任务模式 A（平台编排）依赖这层；模式 B（设备推送）只需 patrol_waypoint + 上报接口。**

### 3.6 系统层

patrol_role_permission（菜单/按钮权限）→ patrol_uri_permission（URI→权限映射，拦截器执行）· patrol_role_data_scope（数据范围=能看哪些区划/分组）· patrol_role_channel_permission（通道级）· patrol_audit_log（@Audit AOP 自动记录）· wvp_user/role（登录与token）。

## 四、模块 → 业务 → 数据（前端侧边栏逐项，以 React 版前端 web-react 为准）

| 模块 | 业务含义 | 读写的主要数据 |
|---|---|---|
| **实时监控 → 视频监控** | 实时看 + 云台 | 通道表(树) → channel/play 播放；PTZ 走 SIP 或 ISAPI |
| **→ 录像回放** | 查历史录像 | wvp_cloud_record（平台录像）+ 国标设备录像查询，合并一个列表 |
| **→ 机器人/无人机监控** | 机器狗画面与状态（待对接） | patrol_robot_device；协议模板 endpoints |
| **巡视管理 → 任务/执行单/结果/告警/报告/统计** | 配置巡检任务、跟踪执行单进度（暂停/恢复/停止）、识别结果复核、告警处置、报告导出 | patrol_task/point/execution + point_result/alarm |
| **设备接入 → 摄像机台账** | **唯一配置入口**：接入/编辑/删除/播放/识别/录像开关/归属 | 通道表 + 派生载体 + patrol_channel_storage |
| **→ 录像计划** | 7×24 或分时段录像模板 | wvp_record_plan/item |
| **→ 录像设备(NVR)** | 存储节点档案（厂商NVR） | patrol_nvr；删除时挂载解绑、归属回落 ZLM |
| **媒体与级联** | ZLM 节点状态、国标级联平台 | wvp_media_server / wvp_platform |
| **组织与地图** | 行政区划树、业务分组、地图布点 | wvp_common_region / group；通道 gb_civil_code |
| **机器人与装备** | 机器人/型号档案/协议/点位/路线 | patrol_robot_device 等 |
| **智能算法** | 识别方案编排（YOLO+VLM+提示词+知识库）、模型连通测试 | patrol_identify_scheme 及其四个子表 |
| **巡视配置** | 告警规则(JSON)/字典/通知/检修区 | patrol_dict / notification / maintenance_area |
| **账号与安全** | 用户管理 / 角色与权限 / 操作审计 / API Key | wvp_user + patrol 权限四表 + audit_log |
| **系统** | 平台信息、运行日志查看 | 运行时状态（不落业务表） |

## 五、人工操作路线（点击 → 数据流动）

### 路线1：接入一台摄像机
```
台账「接入摄像机」→ 向导填 8 项（名称/厂商/IP/端口/账号/密码/通道号/码流，可选挂NVR/区划）
 → POST /patrol/access/test      ZLM 瞬态拉流探活（timeout_sec=6；拉起成功≠出流，另轮询 4×1.2s 确认真出流，总耗时最长约 11 秒）
 → POST /patrol/access/add
    ① wvp_stream_proxy 插入拉流任务（gbDeviceId=3402000000132+随机7位 → 同步建通道行）
    ② startByAppAndStream → ZLM 真正开始拉 RTSP（失败不阻断，可手动拉起）
    ③ 补全通道行关联：stream_id / data_device_id / 名称
    ④ 可选：加入区划(addChannelToRegion)、挂NVR(patrol_nvr_camera)
 → 台账出现一行「RTSP直连」，状态=拉流中（问 ZLM 证实）
```
国标注册路线不用向导：**在设备/PVR 网页配 GB28181 指向平台** → 设备注册进 wvp_device → 目录上报自动建通道（data_type=1）→ 台账自动出现「国标注册」行。
批量路线：台账「导入/导出」→ 下载 Excel 模板（/patrol/access/template，含示例行）→ 填名称/厂商/IP/端口/账号/密码/通道号/码流/区划/自定义URL → /patrol/access/import 逐行复用 add 流程（generic 行必须给完整 RTSP URL），另支持勾选导出设备。

### 路线2：实时观看 + 云台
```
台账「播放」→ /monitor/video?channelId= → GET /common/channel/play
 国标通道: SIP INVITE 点播（⚠ Docker 部署下 NAT 不通，Linux 部署可用）
 RTSP通道: 确保代理在拉 → 返回 flv/hls/rtsp 地址(host=stream_ip=192.168.0.100)
 → 浏览器 http-flv 经 nginx ^~ /live/ → ZLM 8081 → jessibuca 解码
云台: 国标通道走 SIP PTZ 指令；RTSP/挂NVR 通道走 ISAPI(Hikvision Digest:80)——挂了NVR就经NVR下发，
      未挂NVR时从取流地址解析账号密码直连摄像机 ISAPI(通道号固定1)，解析不出凭据则明确提示不可控
```

### 路线3：平台录像 + 回放
```
台账「开启录像」→ 绑定录像计划(record_plan_id) → WVP 每分钟调度器核对 → ZLM startRecord
 → MP4 按小时分段落盘 → ZLM on_record_mp4 hook 回报 → wvp_cloud_record 建索引
 → CloudRecordReconciler 每天 04:10 对账补漏（hook 丢失的孤儿文件补进索引）
回放: 录像回放页 → 按日期合并列出 [国标设备录像] + [平台录像 cloud_record]
 → 平台录像走 ZLM 点播 /mp4_record/；国标设备录像走国标回放（Docker 受限）
```

### 路线4：手动识别（YOLO+VLM 全闭环）
```
台账「识别」→ 选方案 → POST /patrol/access/analyze?channelId=&schemeId=
 → PatrolOrchestrator.analyzeChannelNow:
    ① captureByChannel 抓帧: RTSP通道=ZLM 回环 rtsp://127.0.0.1:{rtsp端口}/{app}/{stream_id}
                              国标通道=先 play 再轮询回环 8×1.5s
    ② 抓帧 JPEG → mediaService.saveBytes → patrol_media(source=MANUAL)
       （ZLM 抓不到流会返回固定"无信号"占位图：按 MD5 指纹识别并视为抓帧失败，
        指纹持久化在 patrol_dict、每日 03:30 自动重新校准，防把占位图当巡检数据）
    ③ CompositeAnalyzer: 方案展开 → YOLO(yolo_service.py:8999) 目检
       → VLM(方案选的模型+提示词+知识库标准值) 研判
    ④ patrol_point_result 落库(NORMAL/ABNORMAL + 置信度 + yolo_json + vlm文本)
    ⑤ ABNORMAL → 自动生成 patrol_alarm + patrol_notification
 → 识别弹窗：画检测框 + 置信度 + 大模型结论；结果在「巡视管理→结果/告警」可查可复核
```

### 路线5：定时巡视（**待机器狗对接方式确定后激活**）
```
patrol_task + task_point(点位→通道/方案) → 生成 execution → 逐点位执行「路线4 的 ①~⑤」
 → 执行单进度(暂停/恢复/停止/进度查询接口已就绪) / 批量结果 / 报告导出(xlsx)
 ⚠ 定时触发调度器尚未实现：当前只能手动执行(POST /api/patrol/task/{id}/execute)
 模式A=平台编排走协议模板控机器狗；模式B=机器狗推送结果上报(/api/patrol/ingest/media)
```

### 路线6：挂载 NVR（厂商录像设备）
```
「录像设备(NVR)」新增（IP/取流端口/ISAPI账号）→ 测试连通 → patrol_nvr
通道「编辑」→ 挂载到该NVR + NVR侧通道号 → patrol_nvr_camera
 → 取流 URL 自动改走 NVR(Channels/{n}01)、云台经 NVR ISAPI、录像归属可选 NVR本机录像
删除 NVR → 挂载自动解绑 + 归属自动回落 ZLM，摄像机本体不受影响
```

## 六、级联规则（删除语义，全部已实现）

| 删除动作 | 级联 |
|---|---|
| 台账-RTSP直连行 | 停 ZLM 拉流 → 删代理任务 → 删通道行 → 清录像归属/挂载。已录 MP4 保留 |
| 台账-国标行 | 删整台国标设备（含其全部通道）。**设备端注册还开着会自动回来**（去设备网页关注册才彻底） |
| 录像设备(NVR) | 挂载解绑 + 归属回落 ZLM。摄像机不受影响 |
| 录像计划 | 通道上的 plan 关联清空，最迟 1 分钟内调度器自动停流停录 |
| 巡视任务 | 执行单/结果/告警保留（历史可溯），任务本身删除 |

## 七、状态的事实源（显示以谁为准）

| 状态 | 事实源 | 说明 |
|---|---|---|
| 国标设备在线 | WVP（SIP注册/心跳） | wvp_device |
| 通道在线 | WVP（目录上报状态） | 通道 gb_status |
| **拉流中/未拉流** | **ZLM getMediaList**（`/patrol/access/stream-online`） | WVP 重启会复位 pulling 标志，不可信 |
| 平台录像"正在录" | ZLM 实际录制状态 | WVP 在录表为内存态(recordStreamMap)，重启即清空、由分钟调度器自愈重建 |
| 录像存在 | wvp_cloud_record（ZLM hook 上报 + 每日对账） | — |
| 存储容量 | 节点档案 + cloud_record SUM(file_size) | — |

## 八、当前状态与待办

- 已全链路验证：接入→拉流→播放(nginx 实收 FLV 106KB/3s)→录像→手动识别→告警入库。
