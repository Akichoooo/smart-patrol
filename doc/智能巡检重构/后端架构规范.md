# 后端架构规范（Java 21 · Spring Boot 3.4）

> **所有 agent / 开发者在本仓库写代码前必读。** 违反"禁止事项"的代码不允许合入。
> 适用范围：`com.genersoft.iot.vmp.patrol` 包（巡检平台新增代码）。stock WVP 代码原则上不动，扩展一律走 patrol 包。

---

## 1. 分层与依赖方向（强制）

```
controller（薄：参数校验 + 权限 + 委托）
    ↓
orchestrator / service（业务唯一归宿）
    ↓
dao（MyBatis 注解 SQL）→ MySQL/ZLM/设备
```

- **Controller 不写业务逻辑**：只做 ①权限检查 ②参数解析 ③调 service/orchestrator ④组装返回。超过 ~30 行的 controller 方法 = 违规。
- **同类业务只有一个核心方法**。多个入口（REST 路由）允许，但必须全部委托到同一核心（参考范式：AI 检测——`PatrolAiController`/`access/analyze`/`ingest/media` 三个入口 → `PatrolOrchestrator.analyzeImageRaw/analyzeChannelNow` 一个核心）。
- **禁止复制"存图/落库/状态更新"之类的胶水代码**。写之前先找有没有现成方法；没有就先抽方法再调用。

## 2. 面向对象与多态（强制）

- **厂商/协议差异 = 策略模式**：核心流程只依赖接口（`ProtocolAdapter`）和注册表（`ProtocolAdapterRegistry`，Spring 收集所有实现 bean → 按 vendor 分发）。**新增厂商 = 新增一个实现类，核心流程零改动**。禁止在核心流程写 `if (vendor.equals("hik")) ...`。
- **封闭的策略族用 sealed**：`sealed interface X permits A, B, C` + switch 模式匹配（编译器保证穷尽性）。
- **多态分发用 Spring 注入 List<T>/Map<String,T>**，不用静态工厂、不用手写 if-else 链。

## 3. Spring 规范（强制）

| 规则 | 做法 | 反例 |
|---|---|---|
| **依赖注入** | `private final` 字段 + 类上 `@RequiredArgsConstructor`（Lombok） | `@Autowired private X x;` 字段注入（唯一例外：`@Autowired(required=false)` 可选依赖） |
| **事务** | `@Transactional` 只包**短而原子的多表写**（如"告警+通知"）；详见 §9-T1 ~ T3 | controller 里多步落库无事务；事务横跨抓帧/VLM 推理等慢 IO |
| **配置** | 一组相关配置用 `@ConfigurationProperties(prefix=...)` record 承接；单个值可用 `@Value`，超过 3 个必须收敛 | 散落十几个 @Value |
| **HTTP 客户端** | 单例 bean（OkHttp/RestClient），禁止方法内 new | 每次调用 new OkHttpClient |
| **异步/定时** | 长任务用 `@Async`（PatrolAsyncConfig 线程池）；定时任务 `@Scheduled` + cron 常量注释 | 在 controller 里 `while + sleep` 长轮询（现状兜底见 §6） |
| **返回值** | 统一 `{code, msg, data}` 由框架包装；业务失败抛 `ControllerException(ErrorCode.xxx)`，不返回裸错误码 | 手拼错误 JSON |

## 4. JDK 21 特性（新代码必须用）

| 特性 | 用法 | 本仓库范例 |
|---|---|---|
| **record** | 固定形状的请求/结果对象：`record AiAnalyzeParam(String source, Integer channelId, ...)` | `PatrolAccessController.AccessParam` |
| **sealed + 模式匹配 switch** | 策略族、结果类型：`switch (obj) { case HikAdapter h -> ...; }` | `ProtocolAdapterRegistry`（instanceof 模式匹配已用） |
| **switch 表达式** | 枚举/字符串分发：`switch (vendor) { case "hik" -> ...; default -> null; }` | `buildRtspUrl` |
| **text block** | MyBatis 注解 SQL、内嵌 JSON 模板（`<script>` 兼容 text block） | 新 SQL 一律 text block，不再 `" + "` 拼接 |
| **List.of / Map.of / record** | 不可变返回 | 随处已用 |
| **Stream API** | 集合转换/过滤，链路清晰为先，不炫技 | `reportList` |

**Optional 约定**：MyBatis mapper 返回值保持 `null` 约定（不过度包装）；controller/service 层对可能为空的结果**尽早抛 `ControllerException`**，不要让 null 往下穿两层。

## 5. 命名与魔法值（强制）

- 状态/类型字符串收敛到常量或枚举（`NORMAL/ABNORMAL/ANALYZING/FAILED`、`ACTIVE/DISABLED`、`ZLM/NVR/NONE`、`MANUAL/ROBOT/PLAYBACK`、`data_type 1/2/3`），**同一字面量出现 ≥3 次必须抽常量**。
- 时间/轮询参数（`timeout_sec=8`、`6×1200ms`）抽成有名字的常量并注释单位。

## 6. 并发与阻塞

- `spring.threads.virtual.enabled=true`（JDK21 虚拟线程）：Tomcat 每请求一线程，controller 里的短阻塞（ZLM 轮询、抓帧 sleep）代价可接受。
- 即便如此：**超过 5 秒的流程必须前端异步化**（先返回受理 + WebSocket/轮询查进度，参考 `PatrolWsEndpoint`），不让 HTTP 请求挂一分钟。

## 7. 数据关联铁律（本项目特有，见《数据关系与模块业务说明.md》）

1. **摄像机 = wvp_device_channel 一行**，是全系统唯一资产核心；载体（SIP设备/拉流代理）是派生影子。
2. 拉流代理通道与代理行的关联字段：`通道.data_device_id = 代理.id`、`通道.stream_id = 代理.stream`（stock 插入拿不到自增 id，接入时显式补全——见 `PatrolAccessController.add`）。
3. **运行状态一律问事实源**：拉流中=ZLM getMediaList；设备在线=WVP注册心跳；录像存在=wvp_cloud_record。禁止把 WVP 数据库里的状态标志当事实（重启会失真）。
4. 删除走级联（见数据关系文档 §六），禁止留下孤儿（ZLM 任务/存储行/挂载行）。

## 9. 吸收自业界规范（条款出处标注，与上文冲突时以本文为准）

### T1. 事务三则（来源：Spring 官方 AOP 语义 + 阿里手册「事务规约」）
- **事务不跨慢 IO**：`@Transactional` 方法内禁止出现抓帧、RTSP 拉流、HTTP 调用、AI 推理、`Thread.sleep`。持连接等 VLM 十几秒 = 连接池杀手。本项目的编排持久化是"先插 `ANALYZING` 再更新终态"的状态机设计，**天然不需要长事务**。
- **自调用失效**：同类内部 `this.method()` 不走代理，`@Transactional`/`@Async` 静默失效。需要事务语义时：拆到另一个 bean，或用 `TransactionTemplate` 编程式。已核查：`analyzeChannelNow → analyzeImageRaw` 的自调用两侧都无事务依赖，安全。
- **回滚语义**：默认只回滚 `RuntimeException/Error`。业务异常统一抛 `ControllerException`（RuntimeException 族）；捕获异常后返回错误 Map 的方法不要再标 `@Transactional`（catch 会吞掉回滚触发）。

### T2. 并发规约（来源：阿里手册「并发处理」）
- 线程池禁止 `Executors.newXxx()` 快捷创建，必须显式参数（本项目 `PatrolAsyncConfig` 用 `ThreadPoolTaskExecutor` + 虚拟线程工厂，已合规）。
- **禁止 `SimpleDateFormat`**（线程不安全），用 `java.time`（`LocalDate.now().toString()` 即 ISO yyyy-MM-dd）或 `DateTimeFormatter`。
- 集合初始化**指定容量**：`new HashMap<>(64)` / `new ArrayList<>(n)`，可预估规模时必填。

### T3. 异常与健壮性（来源：阿里手册「异常日志」+ Effective Java）
- 捕获的异常**必须处理或转抛**，禁止 catch 后留空/只打日志就当没发生；转发时保留原信息（`... : e.getMessage()`）。
- 方法**嵌套 ≤3 层**，超了用卫语句早返回。
- 对外/定时入口必须有兜底：单点位失败不得中断整轮巡检（`runExecution` 已按此实现）。

### T4. 参数校验（来源：Spring Boot 官方）
- 新增固定形状 REST 入参：record + `jakarta.validation` 注解（`@NotBlank/@NotNull/@Min`）+ `@Valid`，在绑定层拒绝脏数据，不在业务代码里散落 if 校验。现存 `Map<String,Object>` 入参（通用实体 CRUD）属已文档化决策，不回改。

### T5. 面向对象（来源：Effective Java 第3版）
- **不可变优先**：能 record/final 就不写可变类（§4 record 规则的理论依据）。
- **组合优于继承**；多参数构造（>4 个）改用 builder 或参数 record。
- 面向接口编程：编排器只依赖 `ProtocolAdapter`/`MediaStorage` 接口，不感知具体实现（六边形/端口-适配器的简化落地）。

### T6. 度量（来源：SonarQube 缺省规则）
- 重复代码：同一文件内重复块 ≥10 行必须抽方法（对"禁止复制胶水"的量化补充）。
- 认知复杂度：单方法超过 15 必须拆分。
